ABSTRACT:

The International English Language Testing System (IELTS) remains the most widely accepted English proficiency examination globally, yet most existing preparation platforms fail to provide automated feedback for subjective skills such as Writing and Speaking, rely heavily on expensive cloud-based APIs for speech processing, and lack personalized learning pathways. This paper presents IELTS Master English AI, a comprehensive IELTS preparation platform built on an Event-Driven Hybrid Architecture that separates computationally intensive AI inference from core business logic. The system employs a NestJS modular monolith as the core backend, a dedicated Python FastAPI microservice for AI processing, and RabbitMQ as the asynchronous message broker connecting them. Key technical contributions include: (1) local speech-to-text processing using Faster-Whisper, eliminating per-request cloud API costs; (2) LLM-based automated Writing and Speaking grading with structured rubric output following official IELTS band descriptors; (3) an SM-2 spaced repetition vocabulary system with custom card types; and (4) a personalized learning roadmap driven by onboarding diagnostics. The system is deployed on Google Cloud Platform using K3s Kubernetes with Traefik ingress. Experimental evaluation demonstrates that the Faster-Whisper integration achieves competitive accuracy with significantly lower latency variance compared to cloud alternatives, while the pronunciation scoring algorithm based on Levenshtein distance effectively discriminates across difficulty levels. The SM-2 simulation validates the algorithm's ability to differentiate user proficiency through adaptive interval scheduling.

Index Terms — IELTS preparation, Event-driven architecture, Speech-to-text, Automated essay scoring, Spaced repetition, NestJS, FastAPI.

I. INTRODUCTION

The International English Language Testing System (IELTS) is recognized by over 11,000 organizations across 140 countries, making it the world's most popular English proficiency test for higher education and migration purposes [1]. With the global surge in online learning, the demand for accessible, AI-driven IELTS preparation tools has increased dramatically. However, a critical analysis of existing platforms reveals several persistent limitations.

First, most commercial applications such as Duolingo and ELSA Speak focus on general English proficiency rather than IELTS-specific exam preparation. They lack structured mock examinations covering all four IELTS skills — Listening, Reading, Writing, and Speaking — in a single integrated environment. Second, automated grading for subjective skills remains a significant technical challenge. While Reading and Listening can be graded deterministically against answer keys, Writing and Speaking require nuanced evaluation of grammar, vocabulary, coherence, and pronunciation — traditionally requiring human examiners. Third, platforms that do incorporate speech analysis typically rely on cloud-based Speech-to-Text APIs (e.g., Google Cloud Speech, Amazon Transcribe), introducing per-request costs, latency variability, and external dependency. Fourth, existing solutions rarely offer personalized learning pathways that adapt to individual learner goals, daily time commitments, and current proficiency levels.

To address these challenges, this paper introduces IELTS Master English AI, a full-stack educational platform engineered specifically for comprehensive IELTS preparation. The system is built upon the following key contributions:

• An Event-Driven Hybrid Architecture that decouples AI inference workloads from core business logic using RabbitMQ as the message broker, ensuring the web interface never blocks during computationally intensive operations such as speech transcription or LLM-based grading.

• Local speech-to-text processing using Faster-Whisper [2], a CTranslate2-optimized implementation of OpenAI's Whisper model, eliminating per-request cloud API costs while maintaining competitive accuracy.

• LLM-based automated IELTS Writing and Speaking grading using Llama 3.3 70B, with strictly enforced JSON output schemas following official IELTS band descriptors across four criteria per skill.

• An SM-2 spaced repetition vocabulary system (Vocab Lab) with customizable card types, field definitions, and templates, enabling Anki-style learning within the platform.

• A personalized learning roadmap generated from onboarding diagnostics (target band, daily study commitment, placement test score), with sequential step-level locking to enforce structured progression.

The remainder of this paper is organized as follows. Section II presents the theoretical background and key algorithms. Section III provides a comparative analysis with existing platforms. Section IV details the system architecture and design of each major subsystem. Section V describes the implementation, deployment, and experimental evaluation. Section VI concludes with a summary and future work directions.

II. THEORETICAL BACKGROUND

A. Event-Driven Architecture

An event-driven architecture (EDA) is a software design pattern in which the flow of the program is determined by events — messages published to and consumed from a message broker. In educational platforms that integrate AI/ML inference, EDA is particularly valuable because operations such as speech transcription (2-10 seconds) and LLM-based essay evaluation (5-30 seconds) would otherwise block the main API thread, degrading user experience. By publishing AI tasks to a message queue (e.g., RabbitMQ) and processing them asynchronously in dedicated worker services, the core backend remains responsive while heavy computations execute independently [3].

B. NestJS Framework

NestJS is a progressive Node.js framework built with TypeScript that employs a modular architecture inspired by Angular. It provides dependency injection, decorators, guards, and interceptors, enabling the construction of scalable and maintainable server-side applications. The framework naturally supports the Modular Monolith pattern, where distinct business domains (e.g., exams, vocabulary, grammar, pronunciation) are encapsulated in separate modules while sharing a single deployment unit [4].

C. FastAPI Framework

FastAPI is a modern, high-performance Python web framework designed for building APIs. Its native async/await support makes it well-suited for I/O-bound AI inference tasks. In this system, FastAPI serves as the dedicated AI worker microservice, leveraging Python's rich ML ecosystem including Faster-Whisper, OpenAI SDK, and scientific computing libraries [5].

D. Faster-Whisper for Speech-to-Text

Faster-Whisper [2] is a reimplementation of OpenAI's Whisper model using CTranslate2, a fast inference engine for Transformer models. It provides up to 4× faster inference with comparable accuracy to the original Whisper implementation. The system uses Faster-Whisper with beam search (beam_size=5) and Voice Activity Detection (VAD) filtering to produce clean transcriptions from user audio recordings.

E. LLM-Based Automated Grading

Large Language Models (LLMs) can be instructed to evaluate text against structured rubrics [6]. This system uses Llama 3.3 70B (via Groq API) as the grading engine, with carefully designed system prompts that enforce:
- Band score assignment (1.0 to 9.0 in 0.5 increments) for each of four IELTS criteria
- Structured strengths, weaknesses, and improvement suggestions
- Specific mistake identification with corrections and explanations
- JSON output schema enforcement for deterministic frontend parsing

The overall Writing band is calculated as:

    Overall = (Task1_Band + Task2_Band × 2) / 3              (1)

This weighting reflects the official IELTS scheme where Task 2 contributes twice as much to the final score.

F. SM-2 Spaced Repetition Algorithm

The SM-2 algorithm, developed by Piotr Wozniak [7], is a spaced repetition scheduling method that optimizes long-term memory retention. Given a quality rating q ∈ {0, 1, 2, 3, 4, 5} after each review, the algorithm updates:

    EF' = EF + (0.1 − (5 − q) × (0.08 + (5 − q) × 0.02))   (2)

where EF is the Ease Factor (minimum 1.3). The review interval is computed as:

    I(1) = 1 day
    I(2) = 6 days                                              (3)
    I(n) = I(n−1) × EF,  for n > 2

If q < 3 (failed review), the repetition counter resets to 0 and the interval resets to 1 day, enforcing re-learning. This mechanism ensures that well-known items are reviewed at exponentially increasing intervals, while difficult items are reviewed more frequently.

G. Levenshtein Distance for Pronunciation Scoring

The system measures pronunciation accuracy using a variant of the Levenshtein edit distance [8]. Given the transcribed text T and target word W, the pronunciation score is computed as:

    Score = (1 − d(T, W) / max(|T|, |W|)) × 100              (4)

where d(T, W) is the minimum number of single-character edits (insertions, deletions, substitutions) required to transform T into W. Both strings are normalized to lowercase before comparison. A score of 100 indicates a perfect match.

H. IELTS Answer Matching Algorithm

For Reading and Listening answer evaluation, the system implements a flexible matching algorithm that handles:
- Alternative answers separated by "/" (e.g., "answer1/answer2")
- Optional words enclosed in parentheses (e.g., "(the) manager")
- Case-insensitive, non-alphanumeric-stripped comparison

This ensures fair grading across the diverse answer formats found in Cambridge IELTS examinations.

B. Key Differentiators

This eliminates per-request API costs (Google Speech-to-Text charges $0.006 per 15 seconds), removes external dependency risks, and provides consistent latency since processing occurs on controlled infrastructure.

IV. SYSTEM ARCHITECTURE AND DESIGN

A. System Architecture Overview

The IELTS Master English AI platform is architected as an Event-Driven Hybrid system comprising three primary layers: the Client Layer, the Application Layer, and the Data Layer. Figure 1 illustrates the high-level architecture.

[FIGURE 1: System Architecture Diagram — use the ASCII diagram from README, redraw as proper figure]

The Client Layer consists of two cross-platform interfaces:
• Web Portal: Built with Next.js 14 (App Router, TypeScript, Tailwind CSS), providing server-side rendering for SEO and performance optimization.
• Mobile Application: Built with React Native (Expo, TypeScript) for native iOS and Android experience.

The Application Layer runs on K3s (lightweight Kubernetes) on Google Cloud Platform and contains:
• Core Backend (NestJS): A modular monolith handling authentication, exam management, learning content, vocabulary, grammar, pronunciation, and shadowing modules. It communicates with the AI Service via RabbitMQ and direct HTTP calls.
• AI Service (FastAPI): A dedicated Python microservice responsible for all ML inferences — Faster-Whisper transcription, LLM-based Writing/Speaking grading, and pronunciation analysis.
• Message Broker (RabbitMQ): Decouples the Core Backend from the AI Service for asynchronous processing of pronunciation checks and exam grading tasks.

The Data Layer comprises:
• PostgreSQL 16: Primary relational database managed via Prisma ORM, containing 35+ models across 10+ domain areas.
• Redis 7: In-memory cache for session data and frequently accessed content.
• MinIO / Google Cloud Storage: Object storage for audio files, images, and media assets.

B. Database Design

The system's data model is designed using Prisma Schema Language and deployed to PostgreSQL. Figure 2 shows the entity-relationship diagram for key domain entities.

[FIGURE 2: ER Diagram — showing key models and relationships]

The database encompasses the following domain groupings:

Core Entities: User (with roles STUDENT, ADMIN, INSTRUCTOR), Exam, ExamSession (with status tracking: IN_PROGRESS → SUBMITTED → GRADING → COMPLETED), and Result (storing per-skill scores and AI feedback as JSON).

IELTS Learning: IeltsSkill → IeltsLesson → IeltsListeningExercise / IeltsReadingExercise / IeltsWritingExercise, with IeltsBasicProgress tracking completion per user per item.

IELTS Advanced: IeltsPracticeListeningPart and IeltsPracticeSession for Cambridge-style part-by-part practice with question-type-level scoring (e.g., form_completion, multiple_choice).

Vocabulary System: VocabularyBook → VocabularyUnit → VocabularyWord / VocabularyExercise / VocabularyQuestion, with VocabularyProgress per user per unit.

Vocab Lab (SM-2): Deck → Flashcard (with interval, repetition, easeFactor, cardState, nextReviewDate fields), FlashcardReview, CardType → CardTypeField / CardTemplate.

Shadowing: ShadowingVideo (with timestamped sentence arrays), ShadowingFolder, and ShadowingDictationProgress.

Grammar: GrammarBook → GrammarUnit → GrammarExercise.

Pronunciation: PronunciationSound (IPA symbols) and PronunciationAttempt (with async status tracking: PENDING → PROCESSING → COMPLETED/FAILED).

C. Authentication and Authorization

The system implements JWT-based authentication via NestJS Guards. Upon login, users receive access tokens. Role-based access control (RBAC) distinguishes between STUDENT, ADMIN, and INSTRUCTOR roles. Redis is used for session caching to reduce database queries for authenticated requests.

D. AI-Powered Grading Pipeline

The AI grading pipeline is the system's most significant technical contribution. Figure 3 illustrates the complete data flow.

[FIGURE 3: AI Grading Pipeline Flow Diagram]

D.1. Writing Grading

When a student submits a Writing exam, the Core Backend sends a synchronous HTTP request to the FastAPI AI Service endpoint /api/v1/writing/grade. The payload contains:
- Task 1 prompt, diagram URL, and student essay
- Task 2 prompt and student essay

The AI Service constructs a carefully engineered system prompt that instructs Llama 3.3 70B to evaluate against four IELTS Writing criteria: Task Achievement, Coherence and Cohesion, Lexical Resource, and Grammatical Range and Accuracy. The model is instructed to respond with a strictly structured JSON containing:
- Band scores (1.0-9.0 in 0.5 increments) per criterion per task
- Lists of strengths, weaknesses, and improvement suggestions
- Up to 10 specific language mistakes with corrections

The server recalculates overall bands to ensure consistency:

    Task_Band = mean(criteria_bands)                           (5)
    Overall = (Task1_Band + Task2_Band × 2) / 3               (6)

Both values are rounded to the nearest 0.5 as per IELTS convention.

D.2. Speaking Grading

Speaking grading follows a three-stage pipeline:
1. Audio Decoding: Base64-encoded audio or URL-referenced audio files are decoded and saved as temporary .webm files.
2. Transcription: Each audio segment is transcribed using Faster-Whisper with beam_size=5 and VAD filtering.
3. LLM Evaluation: The transcriptions are formatted with their corresponding questions and sent to Llama 3.3 70B for evaluation against four Speaking criteria: Fluency and Coherence, Lexical Resource, Grammatical Range and Accuracy, and Pronunciation.

D.3. Pronunciation Checking (Asynchronous)

Unlike Writing and Speaking grading (which are synchronous), pronunciation checking uses the full event-driven pipeline:
1. The Core Backend publishes a task to the pronunciation-check-queue via RabbitMQ.
2. The PronunciationConsumer in the FastAPI service picks up the message.
3. The audio file is downloaded from MinIO object storage.
4. Faster-Whisper transcribes the audio.
5. The Levenshtein-based PronunciationService calculates the similarity score (Equation 4).
6. Results are written directly to PostgreSQL via psycopg2.

This asynchronous approach ensures the student receives immediate acknowledgment while processing occurs in the background.

E. IELTS Exam Engine

The exam engine supports four skill types with distinct grading strategies:

Listening and Reading: Deterministic grading against answer keys. The system implements a flexible answer matching algorithm that handles alternative answers (separated by "/"), optional words (enclosed in parentheses), and multi-select questions. All comparisons are case-insensitive with non-alphanumeric characters stripped.

Writing and Speaking: AI-powered grading as described in Section IV.D.

Session Persistence: The exam session model tracks status transitions (IN_PROGRESS → SUBMITTED → GRADING → COMPLETED → ABANDONED) with JSON-stored answers and precise time tracking. This enables "Save & Pause" functionality, preventing student progress loss.

F. SM-2 Spaced Repetition Vocabulary Lab

The Vocab Lab implements the SM-2 algorithm (Section II.F) with the following features:
• Custom Card Types: Users can define card types with arbitrary fields (e.g., "Vocabulary" with IPA, example sentence, audio) and configure front/back templates.
• Study Queue: Cards are served in priority order — due REVIEW cards first, then LEARNING cards, and finally NEW cards (limited to 20 per session).
• Review Tracking: Each review is logged with a timestamp and quality rating, enabling analytics and progress monitoring.

G. Personalized Learning Roadmap

The roadmap system generates a personalized study plan based on:
1. Onboarding Data: Target IELTS band score, daily time commitment (in minutes), and optional placement test score.
2. Content Interleaving: Items from all skills (Listening, Reading, Writing, Speaking) are interleaved in round-robin fashion to ensure balanced skill development.
3. Time-Based Chunking: Content items are grouped into daily "steps" based on the user's committed study time (lessons ≈ 10 minutes, exercises ≈ 15 minutes).
4. Sequential Locking: Steps are locked sequentially — a user must complete all items in Step N before unlocking Step N+1, enforcing structured progression.
5. Placement Acceleration: Users who score highly on the placement test (>80%) have their first 3 lessons auto-completed, immediately advancing them to more challenging content.

H. Shadowing and Dictation System

The shadowing module allows users to practice with YouTube videos that have been segmented into timestamped sentences. Each sentence includes:
- English text with per-word IPA phonetics
- Vietnamese translation
- Audio start/end timestamps for precise playback

Users can organize videos into custom folders and track completion at the sentence level. The dictation mode offers four difficulty levels (Beginner, Intermediate, Advanced, Expert) that progressively reduce the number of visible hint characters.

C. Experimental Evaluation of SM-2 Spaced Repetition

To validate the pedagogical efficacy of the SM-2 algorithm implementation, a stochastic simulation was conducted over N=50 review iterations using three user profiles:
• User A (High Proficiency): 90% accuracy probability.
• User B (Average Proficiency): 60% accuracy probability.
• User C (Low Proficiency): 30% accuracy probability.

1) Interval Progression Analysis: Figure 9 presents the interval progression for each user profile.

[FIGURE 9: SM-2 Interval Progression — sm2_interval_progression.png]

The results demonstrate that the algorithm successfully differentiates learning behaviors:
• Convergence: User A (90% accuracy, 46/50 correct) achieves exponential interval growth, reaching a maximum of 74,922 days and entering the REVIEW state 41 out of 50 times. User B (60% accuracy, 28/50 correct) shows moderate growth with a maximum interval of 14 days and 15 REVIEW entries, indicating periodic resets from failed reviews. User C (30% accuracy, 20/50 correct) remains with a final interval of only 1 day, reaching REVIEW state merely 8 times — continuous failures reset the repetition counter repeatedly.
• Ease Factor Adaptation: All three users' ease factors decline from the initial 2.5, with User A stabilizing around 1.50 (still allowing moderate interval growth), User B also reaching 1.50 (but with frequent resets), and User C converging to 1.40, near the minimum bound of 1.3, correctly classifying this user as needing maximum reinforcement.

2) Discrimination Capability: The SM-2 algorithm's penalty mechanism (q < 3 triggers interval reset) effectively prevents progression through insufficient knowledge. User C, with 30% accuracy, cannot achieve intervals beyond a few days, ensuring items are reviewed at high frequency until consistent correct responses are demonstrated.

D. Experimental Evaluation of Pronunciation Scoring

To evaluate the Levenshtein-based pronunciation scoring algorithm, we tested [N] pronunciation attempt pairs across three difficulty categories: Basic (common words), Intermediate (multi-syllable words), and Advanced (specialized vocabulary).

1) Score Distribution: Figure 10 presents the score distribution by category.

[FIGURE 10: Pronunciation Score Distribution — pronunciation_score_distribution.png]

The analysis across 51 pronunciation attempt pairs indicates:
• Basic Words (17 samples): Average score of 90.4% with σ=13.5, and a 58.8% perfect match rate, confirming reliable scoring for common vocabulary.
• Intermediate Words (17 samples): Average score of 91.7% with σ=6.7, and a 29.4% perfect match rate. The lower perfect match rate despite the high average demonstrates the algorithm's proportional penalty for minor spelling variations.
• Advanced Words (17 samples): Average score of 90.0% with σ=7.5, and a 23.5% perfect match rate. The consistently declining perfect match rate from Basic → Intermediate → Advanced validates the algorithm's difficulty-level sensitivity.

2) Algorithm Behavior: The Levenshtein-based approach provides three key advantages:
• Proportional Penalty: Single-character errors (e.g., "enviroment" vs "environment") receive proportionally small penalties, while severe mispronunciations receive large penalties.
• Length Normalization: Division by max(|T|, |W|) ensures scores are comparable across words of different lengths.
• Computational Efficiency: Levenshtein distance computation is O(mn) where m, n are string lengths, ensuring real-time scoring capability.

VI. CONCLUSION AND FUTURE WORK

A. Conclusion

This paper presented IELTS Master English AI, a comprehensive IELTS preparation platform built on an Event-Driven Hybrid Architecture. The system integrates a NestJS modular monolith backend with a dedicated Python FastAPI AI microservice, connected via RabbitMQ for asynchronous AI inference processing.

The greatest contributions of this research are:

1) The design and implementation of an Event-Driven Architecture that cleanly separates business logic from AI processing, ensuring responsive user experience even during computationally intensive operations like speech transcription and LLM-based essay grading.

2) The integration of local speech-to-text processing via Faster-Whisper, providing a cost-effective and low-latency alternative to cloud-based Speech-to-Text APIs while maintaining competitive accuracy.

3) The implementation of LLM-based automated grading for IELTS Writing (4 criteria × 2 tasks) and Speaking (4 criteria), with structured JSON output that enables rich, actionable feedback including specific mistakes, corrections, and improvement suggestions.

4) A comprehensive learning pipeline spanning Foundation (Vocabulary, Grammar, Pronunciation) → Basic IELTS (skill lessons and exercises) → Advanced IELTS (part-by-part Cambridge practice) → Intensive IELTS (full mock exams), with SM-2 spaced repetition vocabulary across the entire journey.

The experimental results validate that the SM-2 algorithm effectively differentiates user proficiency through adaptive interval scheduling, and that the Levenshtein-based pronunciation scoring provides discriminative capability across difficulty levels.

B. Future Work

Based on the current implementation, several directions for future development are identified:

1) Teacher Dashboard and Analytics: The database already includes a StudentTeacherLink model. Extending this to a full analytics dashboard would enable instructors to monitor student progress, identify common weaknesses, and assign targeted practice.

2) On-Device ML Processing: Porting the Faster-Whisper model to mobile using TensorFlow Lite or ONNX Runtime would enable offline pronunciation practice without network connectivity.

3) Multi-Test Support: Extending the platform to support TOEFL iBT and PTE Academic examinations, leveraging the existing architecture with exam-specific grading rubrics.

4) Advanced Learning Analytics: Implementing detailed analytical visualizations showing learning velocity, skill balance radar charts, and predictive score estimation based on practice history patterns.

5) Social and Gamification Features: Adding collaborative study rooms, leaderboards, and achievement systems to increase learner motivation and engagement.
