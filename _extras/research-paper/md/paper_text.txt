Abstract— In the context of the growing prevalence of on-
line learning, integrating social elements into foreign language
learning environments has become an inevitable trend. However,
most existing English learning platforms still lack meaningful
learner interaction, fail to leverage multimedia effectively, and
provide limited personalization in learning pathways. This paper
introduces Social-Learning, an English-learning social network
platform developed using a Client-Server architecture. The plat-
form seamlessly combines learning features (listening, writing,
and speaking practice, personalized vocabulary building, and
learning path recommendations) with social networking func-
tionalities (posting, commenting, making friends) and multimedia
communication tools (messaging, voice calls, video calls). The
system is built with Next.js, Node.js, Express.js, React Native,
Supabase, and MongoDB, aiming to deliver a dynamic, interac-
tive, and accessible learning environment. The primary goal of the
platform is to enhance learner motivation, strengthen community
engagement, and expand the potential applications of artificial
intelligence in personalizing English learning content.
Index Terms—Social learning network, English learning,
Cross-platform application, Supabase, Vocabulary personaliza-
tion, Learning path recommendation.
I. INTRODUCTION
Online language-learning platforms have experienced a
significant surge in popularity amid the digital transformation,
with over 500 million users worldwide. Nevertheless, the
majority of such applications revolve around individualized
and automated learning, which leaves a gulf: the absence
of socializing and the actual communicative setting. This
drawback tends to lessen the motivation of the learners and
does not exploit the potential of the multimedia tools to their
full potential [1]. Educational studies, specifically Vygotsky
(1978), have indicated that community-based learning, as
well as social interaction, are imperative in order to promote
the effectiveness of learning and long-term learning habits
[2]. In order to overcome these hurdles, the current paper
presents a social-network-based application called Social-
Learning, which facilitates the process of learning English
and multimedia communication. The system is developed in a
manner that helps combine a structured learning environment
and a loose social network where the learners can not only
practice the skills, but they can also connect, share, and interact
within a global community. The platform is built on a cross-
platform Client-Server architecture (Web and Mobile) and isdeveloped on modern technologies of Next.js and React Native
on the Client side and Node.js/Express.js on the Backend with
a hybrid database system built on Supabase (PostgreSQL) and
MongoDB.
The virtuosity of the Social-Learning is the concept of
the profound combination of the social (posting, making
friends), real-time, multimedia (messaging, voice calls, video
calls) communication features, and a complete complex of
learning tools. The system under consideration is oriented to
the customization of the learning process with the help of
writing, listening, and speaking practice, the mechanism of
managing vocabulary automatically, and the suggested learn-
ing directions. The platform will empower users to monitor
their progress, get feedback, and engage in leaderboards,
which will help to enhance motivation and stick to the habit of
regular learning. Also, administrators are offered monitoring
and analytics tools in the system. The paper is divided into
five parts, and section one is a background of the situation
and solution. Section 2 talks about the theoretical background
and associated technologies. Section 3 outlines the system
architecture and functional subsystems of the system called
Social-Learning. Section 4 records the testing procedure and
experiment assessment. Lastly, Section 5 provides conclusions
and future development directions.
II. THEORETICAL BACKGROUND
A. TypeScript
TypeScript is an open-source software that was created by
Microsoft, and it is regarded as a better version of JavaScript. It
introduces functionality that JavaScript does not have, such as
optional static typing and object-oriented classes. Applications
on the client side (e.g., Angular 2) and the server side
(with Node.js) can be developed in TypeScript. It uses the
ECMAScript 2015 (ES6) features of the language, and is
constantly undergoing updates to adopt the current techniques
of future versions of ECMAScript [3].
B. Next.js
Next.js is an open-source platform created by Vercel and
published in 2016. It is an open-source tool that serves React-
based web apps that are generated with the use of a staticSTUDENT SCIENTIFIC RESEARCH COMMUNICATION, VOLUME I, 2025 2
site and can be rendered on the server side to improve user
experience, web performance, and search engine visibility [4].
C. React Native
React Native React Native is a JavaScript framework that
is applied to create native mobile applications on iOS and
Android. It is grounded on the Facebook React library, but
unlike that, designed to work on mobile platforms rather than
on web browsers. This enables web developers to develop
applications using JavaScript that appear native in the look and
feel. Its best feature is that it can even share a large portion of
the source code between both platforms, and thus it becomes
extremely easy to develop Android and iOS simultaneously
[5].
D. Gemini API
Gemini API The Google Gemini API is a highly powerful
tool that most developers in the modern world can use in
software, applications, and small businesses. The Gemini API
supports text and image input and, therefore, gives the user
insightful and context-aware responses with the ability to
reason intelligently [6].
E. Supabase (PostgreSQL)
Supabase is an open-source Backend as a Service (BaaS)
platform, which includes a set of tools that help to create
applications quickly without the need to manage the servers
manually. It is based on PostgreSQL [7] as a central database
and also provides characteristics like real-time database, user
authentication, file storage, and serverless functions. Supabase
is considered to be an open-source Firebase substitute, in
general [8].
F . Client-Server
Client Server Architecture. The client-server architecture is
a distributed network architecture where the client devices
make service requests to a centralized server, whereby the
server processes the request and responds accordingly. The
server stores resources, and the data processing is done by the
server, the clients access and use these services, which can be
either a computer or a mobile device. Interaction between the
two is based on networking protocols like TCP/IP in order to
promote effective communication [9].
G. Accuracy
The system measures pronunciation accuracy [10] on a scale
of a variant of the Word Error Rate (WER) measure. The
Speech-to-Text API responds by giving the user a text string
(the actual string) when a phrase is pronounced. The compar-
ison between this string and the original one (the expected
string) is made to find out the number of Substitutions (S),
Deletions (D), and Insertions (I). The accuracy is computed
as follows:
Accuracy= 1−S+D+I
N.100%.(1)
In which N represents the number of words in the expected
string. Within the Personal Speaking Practice, 100% Accuracy
is required to complete the system successfully.H. Mastery Score
The Mastery Score is a dynamic score that is updated after
every vocabulary review session. The mastery level M of a
vocabulary item is 0 to 100, and it can be determined as
follows:
• When the user answers correctly:
Mnew=Mold+Pcorrect(2)
• When the user answers incorrectly:
Mnew=max(0, Mold−Pwrong)(3)
In this case, Mnew is the new mastery value, Mold is the old
mastery value, Pcorrect and Pwrong are the reward and penalty
weights (e.g., +5 on each correct and 3 on each incorrect
answer). This process helps to make sure that a user will have
to practice a certain vocabulary item several times before he
or she can understand it [11].

A. System Architecture Overview
The Social-Learning platform is architected as a modern,
distributed system leveraging a client-server model to ensure
scalability, maintainability, and cross-platform compatibility.
The system integrates real-time communication capabilities
with AI-driven learning modules, supported by a hybrid
database infrastructure. Figure 1 illustrates the high-level ar-
chitecture, which comprises three primary layers: the Frontend
Client, the Backend Core, and the External Services & Data
Layer.
1) Frontend Client Layer (Cross-Platform Interface):To
maximize accessibility, the client-side is developed using a
unified codebase philosophy where applicable, targeting both
mobile and web users:
•Mobile Application: Built with React Native, the mobile
app provides a native experience for iOS and Androidusers. It handles device-specific features such as micro-
phone access for speaking practice and camera integration
for video calls.
•Web Application: Developed using Next.js, the web plat-
form offers a responsive and SEO-friendly interface. It
utilizes server-side rendering (SSR) to optimize initial
load times and improve performance for learners access-
ing the platform via browsers.
Both client interfaces communicate with the backend via
secure HTTP requests and WebSocket connections for real-
time interactions.
2) Backend Core Layer (Business Logic & Orchestration):
The backend serves as the central nervous system, built on the
Node.js runtime environment and the Express.js framework.
Hosted on a Digital Ocean VPS, this layer is responsible for:
•API Management: Handling RESTful API requests from
clients, validating user inputs, and managing session
authentication.
•Orchestration: Coordinating interactions between the
database, file storage, and external AI services.
•Real-time Processing: Managing signaling for multimedia
communication (video/voice calls) and instant messaging
features via Socket.IO.
3) Data & External Services Layer (Hybrid Infrastructure):
The system employs a polyglot persistence strategy and inte-
grates specialized third-party services to handle diverse data
types:
a) Hybrid Database System:
•Supabase (PostgreSQL): Acts as the primary relational
database for structured data, including user profiles, learn-
ing progress, social connections, and the “V ocabErrors”
repository. Supabase also manages authentication and
authorization via Row-Level Security (RLS).
•MongoDB: Utilized as a NoSQL database for storing
high-volume, unstructured data such as chat logs and
activity feeds, ensuring efficient retrieval and horizontal
scalability.
b) AI & Cloud Services:
•Google Gemini API: The core engine for theAdaptive
Learning Loop, responsible for generating personalized
learning paths, correcting writing exercises, and powering
the AI conversation partner.
•Google Cloud API: Employed for specialized tasks such
as Speech-to-Text conversion to evaluate pronunciation
accuracy.
•Cloudinary & Supabase Storage: Managed media asset
storage (audio, video, images), ensuring optimized deliv-
ery via Content Delivery Networks (CDNs).
•ZEGOCLOUD: Integrated SDK for high-quality, low-
latency voice and video call functionalities.
•Sepay: Facilitates secure payment processing for pre-
mium features.
4) Deployment & CI/CD:The development lifecycle is
streamlined using GitHub for version control. A Continuous
Integration/Continuous Deployment (CI/CD) pipeline auto-
mates the deployment process: frontend updates are pushed toSTUDENT SCIENTIFIC RESEARCH COMMUNICATION, VOLUME I, 2025 4
distribution platforms, while backend changes are deployed to
the Digital Ocean server, ensuring rapid iteration and stability.

B. Authentication
To address the critical requirements of user data protection
and system integrity, the Social-Learning platform implements
a multi-layered security strategy rooted in the Supabase (Post-
greSQL) ecosystem. The security mechanism is built upon
three pillars: Secure Authentication via JWT, Database-level
Authorization via Row-Level Security (RLS), and Strict API
Key Management.
1) Authentication and Session Management:The system
leverages Supabase Auth (GoTrue) to manage identities, en-
suring that all sensitive credentials are handled securely.
a) Password Protection:All user passwords are automat-
ically hashed and salted before storage, eliminating the risk of
plain-text exposure.
b) JWT Mechanism:Session management relies on
JSON Web Tokens (JWT). Upon successful login, the client
receives a short-lived access token (default 1 hour) and a
long-lived refresh token. This stateless approach allows for
scalability while maintaining security via token revocation
capabilities.
c) Brute-force Mitigation:To prevent unauthorized ac-
cess attempts, the system enforces rate limiting on authentica-
tion endpoints. five consecutive failed login attempts trigger a
mandatory 15-minute lockout period for the account.
d) Multi-Factor Authentication (MFA):To meet non-
functional security constraints, the architecture supports Time-
based One-Time Password (TOTP) MFA, adding a critical
layer of defense against compromised credentials.
2) Authorization via Row-Level Security (RLS):Unlike
traditional architectures that rely on application-level logic
for data protection, Social-Learning enforces authorization
directly at the database layer using PostgreSQL’s Row-Level
Security (RLS).
a) Policy Enforcement:RLS policies act as mandatory
filters for every SQL operation (SELECT, INSERT, UPDATE,
DELETE). For instance, a policy using the auth.uid() functionensures that users can only access their own private vocabulary
lists, even if the API endpoint is technically public.
b) Granular Access Control:By utilizing Custom
Claims within the JWT (e.g., user role), the system imple-
ments Role-Based Access Control. Policies are defined using
USING clauses for existing rows and WITH CHECK clauses
for new data modifications, ensuring that no unauthorized data
manipulation can occur.
c) Defense in Depth:RLS is enabled on all tables by
default. This ensures that even if the client-side code contains
vulnerabilities, the data remains protected at the storage level.
3) Infrastructure and API Security:
a) API Key Segregation:The system strictly distin-
guishes between the anon key (public, client-side safe, re-
stricted by RLS) and the service role key (private, bypasses
RLS). The service role key is exclusively used in trusted
server-side environments (Node.js backend) for administrative
tasks and is never exposed to the frontend.
b) Transport Security:All data transmission between the
Client (React Native/Next.js) and the Server is encrypted using
TLS/SSL, preventing Man-in-the-Middle (MitM) attacks.
c) Secret Management:API keys and database secrets
are managed via environment variables and are rotated peri-
odically to minimize the impact of potential leaks.

C. AI-Based Personalized Learning.
The use of traditional language-learning applications usually
does not involve personalized feedback, which is an essential
element of successful language learning. In order to overcome
this shortcoming, the social-learning system incorporates the
Google Gemini API, a state-of-the-art multimodal AI model,
as the brainchild of its interactive learning capabilities. We do
not simply stick to predefined exercises but instead make use
of AI to create dynamic learning experiences that can analyze,
respond, and interact in real time. The implementation of this
integration is in the form of the Node.js backend that acts as
a middleman and handles the request of the client (Next.js
and React Native) and interacts with the Gemini API. The
workflow is implemented on five major characteristics: (1)
AI-based writing practice and automatic scoring, (2) listening
generated by AI, (3) speaking practice based on AI and in-
teractive conversations, (4) Individual vocabulary acquisition,
and (5) Recommendations based on AI-driven learning paths.
1) Writing Practice :The Writing Practice feature of the
social-learning system is created to assist users in improving
their writing proficiency in English on different topics and at
different levels. The students type their responses in written
form on the interface provided by the system, where this
information is sent to the server to be processed. The written
material is sent to the Gemini API on the backend, whereSTUDENT SCIENTIFIC RESEARCH COMMUNICATION, VOLUME I, 2025 5
it is analyzed in terms of grammar, sentence structure, usage
of vocabulary, and general coherence. The AI then provides
feedback and details, including:
- Overall Score: Calculated based on grammatical accuracy,
vocabulary richness, and logical coherence.
- Improvement Suggestions: Recommends better word
choices or improved sentence structures.
This feedback is shown to the learners as a graphic interface,
with the highlighted parts, and as a detailed explanation.
Wrong words or phrases are also written into the personal
error database (V ocabErrors) to help in individual vocabulary
learning in later modules. Also, the system enables learners
to have an archive of their writing history, therefore, monitor
their progress over the years, compare their average score,
and access sample essays that suit the current level of their
proficiency.
2) Listening Practice :The Listening Practice feature is
developed based on the text-to-speech technology of Gemini
API in combination with audio storage and delivery of Cloud-
inary. The following steps are in the workflow:
a) Content Generation:Gemini API creates brief con-
versations or listening texts, depending on the topic and the
level of proficiency and skills (e.g., daily conversation, travel,
academic contexts).
b) Speech Synthesis:The text thus created is converted
to sounding natural audio, with the pacing and the intonation
being modified to the level of the learner.
c) Playback and Interaction:Students are given audio
and are asked to do tasks like fill-in-the-blank, multiple choice,
or dictation.
d) Scoring:The system uses the responses of the
learners against the original text, and gives accuracy scores
and jots down the vocabulary/grammar errors.
e) Data Storage:The V ocabErrors database stores re-
sults and error data to be analyzed later and provides a
person with specific vocabulary advice. This can enhance the
listening comprehension of the learners, besides offering them
an enriched practice environment by automatically creating
listening exercises, a choice of multiple voices, and control of
speaking rates. The integration plays a key role in promoting
natural exposure and standardization of pronunciation in the
process of learning.
3) Speaking practice:The speaking practice feature is the
only one that will assist the user in enhancing their pronun-
ciation and speaking skills, as well as be used in diagnosing,
gathering, and analyzing personal pronunciation mistakes. This
data helps the platform to offer tailored learning paths. The
system has two modes of practice, one of which serves a
specific purpose:
a) Personal Speaking Mode:It is the mode that focuses
on absolute pronunciation accuracy. There are 10 sample
sentences, which are either static content or AI-generated
in the system. To pass, the users have to pronounce ev-
ery sentence correctly (100%). All words that are identified
as mispronounced are automatically added to the personal
database of the user ( V ocabErrors ). This error data is used
to: recommend individual exercises, track user progress, and
streamline future practice sessions.b) AI-assisted Speaking Mode:It is a mode that is
interested in fluency and contextual conversational ability.
Each user is shown a choice of role (A or B) and engaged in
a 10-sentence dialogue that was produced by the Gemini API.
The threshold passing mode is reduced in the current mode,
which has natural communication; an example is that pro-
nunciation accuracy of 80% must pass. Just like the personal
mode, the words spoken out of pronunciation will be added
to V ocabErrors. This allows the learners to gain confidence
in communication and, at the same time, trace mistakes in
pronunciation as in the personal mode.
4) Personalized Vocabulary :The system does not force
the users to recognize mistakes in their vocabulary, but rather
interferes to assist them in learning the vocabulary. The
process is as follows:
a) Trigger:An automated agent in the system is taken
into action when a particular vocabulary word is logged into
the database (V ocabErrors) as an error and crosses a specified
number (e.g., 5 instances).
b) Vocabulary Set Generation:The agent will automat-
ically generate a custom vocabulary for the user.
c) AI Expansion:This list includes not only the original
mispronounced or abused words. It is forwarded to the Gemini
API (with a special prompt) to be enriched and expanded,
including: synonyms and antonyms, IPA transcription, defini-
tions, and example sentences. This makes the learner have a
profound knowledge of each word and not learn it in isolation.
d) Mastery Score System:The word set of the personal-
ized set has a mastery score attached to each word. The score
rises as the user responds correctly or falls as the user responds
incorrectly, hence a good representation of what the learner has
acquired as knowledge over time. V ocabulary Practice: Besides
the skill-based practice (listening, speaking, and writing), the
system creates exercises depending on the individual vocabu-
lary set, thus giving the learners an opportunity to study and
solidify each word comprehensively.
5) Path of Learning Recommendation:To ensure technical
feasibility and prevent the generation of non-existent content
(”hallucination”), the recommendation engine operates on a
Constrained Generative Model flow
a) Data Collection and Constraint Injection:TheCon-
text Buildermodule (Node.js) aggregates three distinct data
sources to construct a strict input context:
•User Constraints (I u): IncludesSkill Focus(e.g., Speak-
ing),Target Study(e.g., IELTS 6.5),Field Focus(e.g.,
Business/Academic), and critically,Available Timeper
day.
•Learning History (H): Derived from the user’sCurrent
Leveland historicalScore Metricsto determine the ap-
propriate starting difficulty.
•System Syllabus Injection (S): A structured JSON repre-
sentation of the availableExerciseList(containing valid
Topics and Levels) is injected into the prompt. This
constrains the AI to select only topics that actually exist
in the system’s database.
b) Strict JSON Output Schema:The Gemini API pro-
cesses these inputs to generate a personalized roadmap. Unlike
free-text generation, the system enforces a strict JSON schemaSTUDENT SCIENTIFIC RESEARCH COMMUNICATION, VOLUME I, 2025 6
output. This ensures that the Frontend can deterministically
parse the plan into actionable tasks.

VI. CONCLUSION AND FUTURE WORK
A. Conclusion
Social-Learning is a social learning system for learning the
English language (Web and Mobile). With the use of a sepa-
rated Client-Server architecture, the system can incorporate the
latest technologies, including Next.js, React Native, Supabase,
and MongoDB. . . The greatest contribution of the research is
the development and execution of an Adaptive Learning Loop.
The system also uses the Google Gemini API to counter the
absence of personalization in traditional applications; thus,
it does not deliver static learning material. This AI loop,
combined with a well-developed social functionality (adding
friends, posting) and multimedia communication (messaging,
video calls), allows forming an active, strongly interactive
classroom. The results of the implementation are evidence of
the feasibility and efficiency of the offered model with regardto the necessity of the English learning platform, which is not
only community-focused but also highly personalized.
B. Future Work
According to the obtained outcomes, the research group
suggests several ways to develop the system further:
Optimizing AI Performance: Enhance the speed of AI
capabilities. Optimize the messages to the Gemini API to make
the writing evaluation more accurate (Figure 5) at a lower
API cost. Improving Analytics: Adding to the “Your Progress”
page, include more of the detailed analytical charts about the
learning activities of the users, to enable them to easily learn
what they were strong in and weak in, and how much time
they spent on the particular skills. System Performance and
Security: Optimize system components such as Nginx and
API performance to process the high traffic, especially during
peak learning periods. Enhance security controls, particularly
user data protection, to address high security requirements and
system safety.
